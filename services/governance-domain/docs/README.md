# governance-domain

## 1. 为什么需要这个域

导购内容平台同时承担 **用户体验、商业合规与运营可控性**。若把审核、下架、商业合作标识、风险标记与策略执行散落在各内容或推荐服务中，会出现：

- 规则口径不一致（同一内容在不同入口可见性不同）
- 变更成本高（改一条策略要动多个服务）
- 审计与追责困难（谁、何时、因何改变可见性缺少统一记录）

**governance-domain** 把「平台治理与运营支撑」收敛为单一业务能力边界：对外提供统一的治理决策与配置面，供内容展示、推荐编排、网关等消费方查询或订阅，从而支撑 **文档先行、多团队并行开发** 时的稳定契约。

## 2. 职责范围（Scope）

本域负责：

| 能力 | 说明 |
|------|------|
| **内容审核（Content review）** | 审核队列、审核结论、审核意见与版本；与内容实体的绑定关系（内容由 content-domain 持有，本域持有审核态与结论）。 |
| **商业合作标识（Business cooperation labeling）** | 内容/卡片/专题等维度的合作类型、披露标签、展示义务相关元数据；供客户端与合规展示消费。 |
| **发布/下架控制（Publish / unpublish）** | 治理视角的可见性裁决：上线、下架、仅内测、区域/渠道差异化可见等；**不**替代内容域的草稿/定稿编辑流程，但可覆盖最终对用户是否可见。 |
| **运营配置（Operational configuration）** | 平台级开关、阈值、名单、维护模式、功能灰度等与治理/运营相关的配置项；需版本化与审计。 |
| **风险标记（Risk flags）** | 内容、账号、渠道等维度的风险标签、等级、来源与过期策略；供策略与人工复核使用。 |
| **策略执行（Policy enforcement）** | 将书面/配置化的策略落地为可计算的判定（如：某类内容必须带披露、某风险等级禁止对外展示）；输出明确决策供调用方执行。 |

## 3. 边界（Boundaries）

### 3.1 本域拥有

- 审核工作流状态、审核记录、治理侧可见性决策的权威数据源（在本域库表或明确归属的存储中）。
- 商业合作与披露相关 **治理元数据** 的定义与变更审计。
- 运营配置项的模式定义、发布流水线、回滚与生效范围。
- 风险标记的生命周期与策略引用关系（标记本身在本域；业务事实由其他域提供时可仅存引用 ID）。

### 3.2 本域不拥有（由其他域负责）

| 边界外能力 | 归属建议 |
|------------|----------|
| 导购正文、媒体资产、专题结构、卡片业务字段 | **content-domain** |
| 召回、排序、多样性、推荐解释与流量实验 | **recommendation-domain** |
| 联盟平台 API、转链、佣金参数、渠道适配 | **affiliate-domain**、**tracking-domain** |
| 用户账户、登录会话、个人偏好 | **user-domain** |
| 统一入口鉴权、限流、路由 | **gateway** |

### 3.3 协作原则

- **内容实体 ID** 以 content-domain（或契约约定）为准；本域只存 `content_id` 等引用与治理叠加态。
- **推荐结果是否展示** 由 recommendation-domain 编排，但 **是否允许对最终用户展示** 须服从本域的可见性/策略判定（可同步查询或异步订阅，见 `api.md` / `workflow.md`）。
- **联盟跳转与归因** 的技术实现不在本域；本域可要求「某类内容必须满足披露配置后才允许进入某跳转模板」，具体跳转由 tracking/affiliate 执行。

## 4. 依赖（Dependencies）

### 4.1 上游 / 被依赖的数据与事件

- **content-domain**：内容创建/更新事件、内容类型与渠道信息，用于入审与策略匹配。
- **user-domain**（可选）：审核员账号、角色、操作者身份断言（也可由网关 + IAM 统一注入）。
- **公共契约**（`docs/contracts/`）：错误码、分页、鉴权约定；导购卡片与推荐协议中与本域相关的字段（如披露标签、可见性）需在契约中列明来源为本域。

### 4.2 下游 / 消费方

- **gateway**：运营后台、审核后台 API 聚合（BFF 职责由 gateway 承担）。
- **content-domain**：读取可见性或与编辑流合并（若采用「内容域写草稿、治理域裁定上线」模型）。
- **recommendation-domain**：在排序前后过滤或降权（本域提供判定接口或快照，**不**实现排序逻辑）。
- **客户端**：读取披露与合规展示所需字段（通常经 BFF 裁剪）。

## 5. 非目标（Non-goals）

- 不实现 **推荐排序、召回、重排、解释文案生成**。
- 不实现 **拼多多/抖音等联盟侧 API 对接、签名、佣金试算**。
- 不承担 **通用 CMS 的全文编辑、多媒体处理**（仅治理叠加态与配置）。
- 不替代 **法务出具的具体条文**；本域实现的是可执行的策略与配置，法律解读在流程外完成。
- 不承诺 **实时风控反欺诈全链路**（可与专业风控系统对接，本域保留标签与策略挂载点）。

## 7. 并行开发提示

- 接口与字段以 **api.md + data-model.md** 为谈判桌；实现前对齐契约版本号。
- 若消费方仅需「是否可展示」，优先约定 **轻量判定接口** 或 **版本化快照**，避免每次推荐全量拉取治理详情。
- 所有影响用户可见性的变更应可走 **审计 ID**（见 data-model / workflow）。
