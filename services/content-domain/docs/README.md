# content-domain

## 1. 服务目标

`content-domain` 负责把选品与编辑意图沉淀为**可分发、可引用、可版本化**的导购内容资产，并向网关与推荐域提供稳定的内容读取面。目标是让衣、食、住、行场景下的专题、榜单、攻略与商品/服务卡片在多端呈现时语义一致，且与联盟跳转、治理审核的职责清晰分离。

## 2. 职责范围（本域负责）

- **导购内容实体**：攻略、短文、说明型内容等可展示单元的创建、更新、版本与发布状态（在治理规则允许范围内）。
- **专题（专题页 / 集合）**：专题元数据、版面结构引用、所含内容条目顺序与生效区间。
- **榜单**：榜单定义、条目列表、排序规则说明（榜单的“展示顺序”属于内容；个性化重排由 `recommendation-domain` 负责）。
- **商品/服务卡片**：结构化导购卡片（标题、卖点、媒体、主题标签、渠道侧商品标识引用等），供列表、详情与推荐结果装配使用。
- **衣食住行主题管理**：主题树或扁平主题枚举的配置、内容与卡片的主题归属、主题级运营文案与入口配置（不含推荐策略本身）。

## 3. 非职责范围（本域明确不拥有）

- **用户与个性化**：账户、登录态、画像、收藏、历史、反馈等 → `user-domain`。
- **推荐策略**：召回、排序、多样性、解释文案策略 → `recommendation-domain`（可消费本域内容 ID 与特征）。
- **联盟平台对接与佣金参数**：渠道 SDK、联盟 API、佣金比例与渠道能力封装 → `affiliate-domain`。
- **推广链接生成与点击归因**：转链、跳转中间页、点击日志、归因 ID → `tracking-domain`。
- **审核流与强制管控**：审核队列、违规下架、商业合作强制标识规则执行 → `governance-domain`（本域执行治理判定结果，不定义治理规则全集）。
- **交易、支付、履约**：订单、支付、物流、售后 → 平台范围外，本域不涉及。
- **网关横切能力**：统一鉴权、限流、路由、聚合 → `gateway`。

## 4. 上下游依赖

### 上游（调用本域或向本域写入）

| 来源 | 关系说明 |
|------|----------|
| `gateway` | 对外暴露的读接口与运营写接口经网关统一入口；本域不直连客户端。 |
| 运营后台 / CMS（实现可落在本域或独立 BFF） | 专题、榜单、卡片、攻略的编排与发布；需服从 `governance-domain` 的发布门槛。 |
| `governance-domain` | 下发可见性（如上架/下架/仅审核可见）、商业标识要求；本域持久化生效状态。 |

### 下游（本域调用或依赖）

| 目标 | 关系说明 |
|------|----------|
| `affiliate-domain`（可选、异步或编排侧） | 解析或校验渠道侧商品/店铺标识是否仍有效时，可通过契约查询；**卡片上的渠道引用 ID 以本域存储为准**，具体转链不在本域。 |
| `governance-domain` | 发布前校验、审核状态查询；本域不实现完整审核引擎。 |

### 数据消费方（只读本域）

| 消费方 | 说明 |
|--------|------|
| `recommendation-domain` | 按内容 ID、主题、标签拉取特征或摘要供召回排序；不修改本域主数据。 |
| `gateway` / 客户端 | 列表、详情、专题页、榜单页展示。 |

## 5. 与顶层架构的一致性

- 衣、食、住、行是**内容主题与运营视图**，不是独立微服务；主题维度由本域建模并对外提供。
- 跨服务字段口径以 `docs/contracts/` 下契约为准（如导购卡片、分页、错误码）；本域文档描述内容域特有的实体与接口，不重复定义全局契约全文。
