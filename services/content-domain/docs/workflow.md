# content-domain 业务流程

本文档描述**创作、审核联动、发布、分发只读**四条主链路。不涉及转链、支付与履约。

## 1. 总览

```text
运营创作 -> 提交审核（governance）-> 发布生效（content）-> 网关/推荐消费 -> 用户浏览
```

- **写路径**：以内容域主数据为准，治理域决定能否真正对用户可见。
- **读路径**：高并发、可缓存；默认只暴露 `PUBLISHED`（及 `SCHEDULED` 到时自动切换，若产品启用定时发布）。

---

## 2. 导购卡片与图文：创作与修订

### 2.1 新建草稿

1. 运营在 CMS 填写卡片或图文基础信息，保存为 `DRAFT`。
2. 本域分配 `card_id` / `content_id`，写入最小可编辑记录。
3. 可多次 `Upsert*`，`revision` 递增。

### 2.2 嵌入与引用

- 图文块中嵌入卡片：仅保存 `card_id` 引用；**被引用卡片下架时**，详情页由网关或客户端按本域返回状态展示占位或隐藏块（具体产品规则在验收文档中固定）。

### 2.3 主题与标签绑定

- 运营选择 `theme_ids` / `tag_ids`；本域校验 ID 存在且 `ACTIVE`。
- 衣、食、住、行大类通过 `Theme.life_theme` 派生，不要求运营重复手选四个顶层枚举（可实现为自动写入 `life_theme` 冗余字段便于筛选）。

---

## 3. 审核联动（与 governance-domain）

### 3.1 提交审核

1. 运营执行 `SubmitForReview`，本域将状态从 `DRAFT` 置为 `IN_REVIEW`，并锁定或标记可编辑性（实现策略：软锁 + 提示）。
2. 本域向 `governance-domain` 投递审核任务（异步消息或直接 RPC，以实现为准），携带：实体类型、实体 ID、`revision`、摘要字段。

### 3.2 审核结果回传

1. **通过**：治理回调或本域轮询获取结果 → 本域可置为 `PUBLISHED` 或 `SCHEDULED`（若设定了生效时间），但最终用户可见性仍以治理裁决为准。
2. **驳回**：状态回 `DRAFT` 或 `IN_REVIEW` 带驳回原因码，由契约定义；本域持久化驳回原因供 CMS 展示。
3. **强制下架**：治理主动下发 → 本域将 `content_status` 置为 `OFFLINE`，读接口立即不可见或返回治理错误码。

本域**不实现**敏感词引擎、图片鉴黄等；仅保存治理结论与展示策略字段（如 `commercial_disclosure_required` 是否强制为 true）。

---

## 4. 发布与生效

### 4.1 即时发布

- 审核通过后，运营显式触发 `PublishRevision`；v1 默认不采用“审核通过即自动上线”。
- 对外读接口仅返回当前 `published_revision` 对应快照（推荐做法：不可变快照，避免在线编辑影响已缓存读者）。
- 即使存在 `published_revision`，若治理裁决不是 `published`，用户侧读链路仍应视为不可见。

### 4.2 定时发布

- `effective_from` 到达后，调度任务或懒读切换将状态视为对已读流量 `PUBLISHED`。
- `effective_to` 到期后可自动 `OFFLINE` 或降级为列表不可见（与产品一致）。

### 4.3 版本回滚

- 保留历史 `revision`；回滚即把 `published_revision` 指向上一稳定版本并记录审计（细节实现期定稿）。

---

## 5. 专题与榜单编排流程

### 5.1 专题

1. 创建 `Topic` 草稿，添加 `modules` 与 `items`，引用已存在或已发布的 `card_id` / `content_id` / `ranking_id`。
2. 提交审核 → 发布；专题自身状态与引用目标状态**独立**：引用对象下架时，专题页展示降级策略由产品定义（如灰显“暂时不可用”）。

### 5.2 榜单

1. 创建 `RankingList`，维护有序 `entries`。
2. 审核发布；**顺序调整**可走轻量流程（是否需再审由 governance 规则决定）。

---

## 6. 内容分发只读链路（用户侧）

```text
客户端请求 -> gateway ->（可选）recommendation-domain 产出 ID 列表
          -> content-domain BatchGet / Get* -> 合并响应 -> 客户端渲染
```

### 6.1 缓存与一致性

- 读多写少：`GetTopic`、`GetRankingList`、`BatchGetGuideCards` 等适合 CDN / Redis 短缓存。
- 下架与治理变更：依赖缓存 TTL + 主动失效（消息总线通知网关/缓存层，实现期定稿）。

### 6.2 与推荐域协作

1. `recommendation-domain` 输出内容 ID（卡片、图文、专题入口等）。
2. 网关或 BFF 调用本域批量拉取展示字段。
3. 本域**不回调**推荐域；避免循环依赖。

---

## 7. 异常与补偿

| 场景 | 行为 |
|------|------|
| 审核服务超时 | 本域保持 `IN_REVIEW`，CMS 显示处理中；禁止重复发布 |
| 部分 card_id 缺失 | `BatchGetGuideCards` 返回 `missing_ids[]`，网关决定过滤或报错 |
| 专题引用已删除实体 | 列表项跳过或展示占位，记录监控告警供运营修复 |

---

## 8. 文档维护

流程变更（如审核与发布合并、定时发布是否一期上线）须同步更新本文档与 `changelog.md`，再进入实现。
