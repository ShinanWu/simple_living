# 页面规格与状态定义

## 1. 通用状态模型

- `loading`：首次加载或关键区块加载中
- `success`：数据可展示且可交互
- `empty`：请求成功但无内容
- `error`：请求失败或数据不可用
- `offline`：网络不可用或弱网超时降级

## 2. 首页（Home）

### 2.1 核心模块

- 顶栏：搜索框（占位，placeholder「搜索少糖推荐」）+ 右侧「我的」入口图标
- 当前主题推荐单卡片（主模块，一屏仅 1 条），卡片拆分为两块：`图片区`（主视觉）与`推荐理由区`（两行省略）
- 底部主题切换栏：`衣`、`食`、`住`、`行`（固定在页面底部，便于单手切换）
- 卡片主动作（查看详情/去购买）

### 2.2 顶栏交互

- 搜索框为只读占位态，点击弹出提示"搜索功能即将上线"（v1）；v2 跳转搜索页
- 「我的」图标点击导航到我的页
- 顶栏不使用卡片容器，高度紧凑，最大化卡片区可用空间

### 2.3 关键交互

- 底部主题栏支持点按切换，且支持左右滑语义切换
- 上滑：下一条
- 下滑（非第一页）：上一条
- 下滑（第一页）：二段提示，松手判定刷新
- 到最后一条后继续上滑：展示收尾提示“少糖就先到这里吧”，并停留在最后一条（不回到首页）
- 点击卡片进入详情：顶部为多图画廊（左右滑切换），下方展示完整文案，页面支持纵向滚动

## 3. 验收口径（页面级）

- 每页五态可被测试复现且行为一致
- 首页四个主题 Tab 均可独立通过核心流程验收（浏览 -> 详情 -> 去购买）

## 4. 登录（Login）

### 4.1 核心模块

- 登录面板（可从“我的页去登录”或受保护动作触发）
- 登录方式：`微信登录`、`手机号注册/登录`
- 手机号子流程：手机号输入、验证码输入、倒计时重发
- 用户协议与隐私说明区（固定展示）

### 4.2 关键交互

- 默认突出微信主按钮，手机号入口同层可用
- 手机号输入后先做前端格式校验，再标准化为 `phone_e164`
- 验证码发送后进入倒计时，倒计时内禁用重发按钮
- 登录成功后关闭面板并回跳到触发前的业务动作
- 登录失败保留上下文，允许原位重试，不丢失来源动作

### 4.3 页面状态

- `idle`：展示登录方式和协议提示
- `authorizing`：微信授权中
- `phone_input`：手机号输入
- `otp_sending`：验证码发送中
- `otp_input`：验证码输入
- `issuing_token`：向网关换 token
- `error_retryable`：可重试错误
- `error_blocking`：不可立即重试错误
- `success`：登录成功，回跳来源页

### 4.4 验收口径（登录页）

- 微信登录可完成“授权 -> 发 token -> 回跳来源动作”
- 手机号登录可完成“输入手机号 -> 验证码 -> 发 token -> 回跳来源动作”
- `code=20002` 会触发 refresh；`code=20003` 则回退访客态并重新引导登录
- 登录失败不会造成页面卡死或重复提交
