# 前端跨端交互共识（全局）

## 1. 目标

本文是 `Web / iOS / Android` 全前端交互的统一语义文档，用于约束：

- 用户可感知行为一致
- 状态与恢复路径一致
- 埋点语义一致

后续新增页面或功能的交互规则，默认都先落在本文，再进入分端实现文档。

## 2. 适用范围

- 首页、详情页、跳转准备页、我的页
- 后续新增页面与组件交互
- 全局导航、手势、反馈、异常恢复、埋点语义

## 3. 不可分叉原则（必须一致）

### 3.1 任务语义一致

- 相同行为在三端表达同一业务意图
- 不允许因平台差异改变核心任务路径

### 3.2 状态语义一致

- 页面状态统一为：`loading` / `success` / `empty` / `error` / `offline`
- 同类状态文案和恢复动作保持同语义

### 3.3 交互触发时机一致

- 关键动作触发时机跨端一致（例如“刷新在松手时判定”）
- 可以调整阈值与动画，但不能改变触发条件语义

### 3.4 契约消费一致

- 前端交互不得发明与 `gateway` 契约冲突的字段语义
- 埋点字段命名与含义在三端保持一致

## 4. 全局交互规则

### 4.1 导航与返回

- 底部导航仅支持点按切换
- 系统返回优先级高于页面自定义手势
- 返回后应恢复用户最近一次可理解上下文

### 4.2 手势冲突处理

- 横向与纵向手势按主方向判定，禁止同时触发
- 拖拽手势进行中，不得误触发点击进入
- 非关键区域手势不得抢占关键操作区域

### 4.3 加载与反馈

- 首屏加载提供明确反馈，不阻塞核心导航结构
- 长请求需要可见状态与可恢复入口
- 重试按钮语义统一为“重试当前操作”

### 4.4 空态与异常恢复

- 空态给出下一步动作（重试或返回）
- 异常优先恢复当前任务，再建议返回上一级
- 离线态明确提示并允许用户重试

## 5. 首页（Home）共识规则

### 5.1 首页结构

- 顶部：主题入口（衣、食、住、行）
- 主区：单屏单卡片（一次只展示 1 条推荐）
- 底部：应用导航（首页/我的）

### 5.2 手势语义

- 左滑/右滑：切换 `衣/食/住/行`
- 上滑：下一条推荐
- 下滑（非第一页）：上一条推荐
- 下滑（第一页）：进入二段式刷新判定

### 5.3 刷新判定

- 下拉过程中只更新视觉反馈，不触发请求
- 仅在松手时判定是否刷新
- 松手时位移 >= 刷新阈值：触发刷新
- 松手时位移 < 刷新阈值：回弹，不刷新
- 若超过阈值后回拉到阈值内再松手：不刷新

### 5.4 首页文案

- 阈值前：`继续下滑刷新`
- 阈值后：`松手刷新`

## 6. 埋点语义共识

- 事件命名按“页面_动作_结果”统一风格
- 字段命名使用 snake_case，含义跨端一致
- 至少覆盖：入口点击、主要手势、刷新触发、错误恢复

## 7. 变更流程

- 新增或修改交互：先改本文，再改分端文档，再改实现
- 分端文档不得覆盖或弱化本文的统一语义
- 若实现与文档冲突，以已评审文档为准并回修实现
