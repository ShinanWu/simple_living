# 错误码约定（Error Codes）

## 1. 目的

用**整数 `code`** 表达可程序化处理的结果，与 [common-response.md](./common-response.md) 顶层 `code` 及 `errors[].code` 对齐；按区间划分业务域，便于多端与多服务并行实现。

## 2. 全局规则

| 规则 | 说明 |
|------|------|
| 成功 | `0` 表示成功，且通常配合 `success: true` |
| 区间 | 五位数 `ABCDE`：`A` 为域大类，后四位为域内序号；同一语义跨版本保持同一数值 |
| 文案 | `message` 可本地化，**不得**要求客户端用 `message` 做分支 |
| 扩展 | 域内仅允许**追加**新码；已发布码的语义不可改为相反含义 |

## 3. 域区间总表

| 区间 | 域 | 说明 |
|------|-----|------|
| `0` | 成功 | 唯一 |
| `10000`–`10999` | 通用客户端 / 请求 / 网关入口 | 参数、格式、限流、版本、网关入口校验等 |
| `20000`–`20999` | 鉴权与会话 | 未登录、令牌无效、权限不足 |
| `30000`–`30999` | 内容与导购 | 卡片、专题、资源不存在或不可见 |
| `40000`–`40999` | 推荐 | 召回失败、场景不支持、空结果（若需区分） |
| `50000`–`50999` | 联盟与跳转 | 转链失败、渠道不可用、链接过期 |
| `60000`–`60999` | 治理与合规 | 下架、审核中、地域限制 |
| `90000`–`90999` | 系统 | 内部错误、依赖超时、不可预期故障 |

## 4. 常用码（预留，可随实现细化）

### 4.1 通用（10xxx）

| code | 语义（机器） | 典型 HTTP |
|------|----------------|-----------|
| `10001` | 缺少必填参数 | 400 |
| `10002` | 参数校验失败 | 400 |
| `10003` | 不支持的内容类型或编码 | 415 / 400 |
| `10004` | 接口版本不支持 | 400 / 426 |
| `10005` | 请求频率超限 | 429 |
| `10006` | 请求体过大 | 413 |

说明：

- `10000`–`10049` 保留给通用请求语义
- `10050`–`10099` 预留给 `gateway` 入口层错误映射与基础防护

### 4.2 鉴权（20xxx）

| code | 语义 | 典型 HTTP |
|------|------|-----------|
| `20001` | 未登录或会话缺失 | 401 |
| `20002` | 访问令牌无效或过期 | 401 |
| `20003` | 刷新令牌无效或过期 | 401 |
| `20004` | 权限不足（已识别用户） | 403 |
| `20005` | 设备或环境被拒绝 | 403 |

### 4.3 内容（30xxx）

| code | 语义 | 典型 HTTP |
|------|------|-----------|
| `30001` | 资源不存在 | 404 |
| `30002` | 资源已下架或不可见 | 410 / 404 |
| `30003` | 资源未发布 | 404 |

### 4.4 推荐（40xxx）

| code | 语义 | 典型 HTTP |
|------|------|-----------|
| `40001` | 推荐场景未知或不支持 | 400 |
| `40002` | 推荐服务暂时不可用 | 503 |
| `40003` | 推荐上下文不足，已降级到默认推荐（通常不作为公开失败返回） | 200 |

### 4.5 联盟与跳转（50xxx）

| code | 语义 | 典型 HTTP |
|------|------|-----------|
| `50001` | 渠道不可用或维护中 | 503 |
| `50002` | 推广链接生成失败 | 502 / 500 |
| `50003` | 链接已失效 | 410 |

### 4.6 治理（60xxx）

| code | 语义 | 典型 HTTP |
|------|------|-----------|
| `60001` | 内容因合规被拦截 | 451 / 403 |
| `60002` | 地域或策略限制 | 403 |

### 4.7 系统（90xxx）

| code | 语义 | 典型 HTTP |
|------|------|-----------|
| `90001` | 内部错误 | 500 |
| `90002` | 依赖服务超时 | 504 |
| `90003` | 依赖服务错误 | 502 |

## 5. 与 `errors[]` 的关系

字段级错误可使用与顶层相同的域内码（如多个 `10002`），或在该域内分配子码；须在具体接口契约中说明是否返回 `errors` 数组。

默认规则：

- 顶层 `code` 表示本次请求最主要的失败原因
- `errors[].code` 用于更细粒度的字段或子资源错误
- 客户端分支逻辑优先看顶层 `code`，再按需消费 `errors[]`
